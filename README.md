# 飲食店向け POS・オーダー管理システム

1店舗・オンプレミス（店内サーバー）で動く、レジ・キッチン・カスタマーモニター・ピックアップの Web システム。
要件は [docs/requirements.md](docs/requirements.md)、開発計画は [docs/development-plan.md](docs/development-plan.md) を参照。

> 現在の進捗: **フェーズ5（返金・変更）まで完了**。注文フロー、レシート（プレビュー・PDF）、取引検索・全額/一部返金・商品変更まで動く。売上確認・精算・CSV・操作ログ閲覧はフェーズ6。

## 構成

| パス | 内容 |
| --- | --- |
| `apps/server` | API・リアルタイム配信（Fastify + Socket.IO + Drizzle + SQLite） |
| `apps/web` | 全端末共通の Web アプリ（React + Vite） |
| `packages/shared` | 型・入力検証・イベント定義・金額/税計算・注文の状態遷移 |
| `e2e/` | Playwright による通しの E2E テスト |
| `docker/`, `compose.yaml` | 店内サーバー用の Docker 構成（アプリ + Caddy による HTTPS） |

## 端末ごとの URL

| 端末 | URL | 備考 |
| --- | --- | --- |
| 端末登録 | `/pairing` | 未登録の端末は自動でここに移る |
| レジ | `/register` | レジ番号を選び、従業員コード + PIN でログイン。未開設なら釣銭準備金を入れて開設 |
| キッチンモニター | `/kitchen` | 表示範囲（すべて／フード／ドリンク）を端末ごとに保存 |
| カスタマーモニター | `/customer` | 起動時に1回タップして音声（チャイム）を有効にする |
| ピックアップ端末 | `/pickup` | iPhone の画面幅にも対応 |
| 管理画面 | `/admin` | 端末登録不要。管理者ログイン必須 |

登録済みの端末は `/` を開くと自分の役割の画面に移動する。

## 開発環境での起動

Node.js 22 以上（開発は 24）と corepack が必要。pnpm は corepack 経由で使う。

```bash
corepack pnpm install
```

```bash
cp apps/server/.env.example apps/server/.env
```

```bash
corepack pnpm dev
```

- Web: http://localhost:5173 （`/api` と `/socket.io` はサーバー :3000 へプロキシ）
- 初回起動時、`apps/server/.env` の `INITIAL_ADMIN_CODE` / `INITIAL_ADMIN_PASSWORD` で管理者が作られる（従業員が0人のときだけ）。初期管理者の PIN は `0000`
- DB は `apps/server/data/pos.sqlite`

テストと型チェック:

```bash
corepack pnpm test
```

```bash
corepack pnpm typecheck
```

E2E テスト（Web をビルドし、一時 DB でサーバーを起動して通しで操作する。初回だけブラウザの導入が必要）:

```bash
npx playwright install chromium
```

```bash
corepack pnpm test:e2e
```

DB スキーマを変えたらマイグレーションを生成する:

```bash
corepack pnpm db:generate
```

## 店内サーバー（Ubuntu + Docker）での起動

詳しい手順書はフェーズ7で整備する。現時点の最小手順:

1. `cp .env.example .env` して管理者の初期パスワードを変える
2. `mkdir -p data && sudo chown 1000:1000 data`（コンテナ内の node ユーザーが DB を書けるように）
3. `scripts/create-certs.sh <サーバーのIP>` で HTTPS 証明書を作る（mkcert が必要）
4. `docker compose up -d --build`
5. iPad/iPhone は `http://<サーバーのIP>/rootCA.crt` を開いて CA 証明書をインストールし、「設定 > 一般 > 情報 > 証明書信頼設定」で信頼する
6. 各端末で `https://<サーバーのIP>/` を開く

## 端末の初期設定

1. PC で `/admin` を開き、管理者でログインする
2. 「端末」画面で役割を選び、ペアリングコード（6桁・10分有効）を発行する
3. 登録する端末で `/pairing` を開き、コードと端末名を入力する
4. 管理画面の「登録済みの端末」に表示され、接続中なら「オンライン」になる
5. 「通信テスト」で送信すると、全端末の画面下部に通知が出る

## 管理画面のマスタ（フェーズ2）

| 画面 | 内容 |
| --- | --- |
| 商品 | 商品名・キッチン略称・税込価格（持ち帰り別価格も可）・税区分・カテゴリ・ステーション・オプショングループ・表示順・ボタン色・売切・有効。CSV 出力／取り込み |
| カテゴリ | レジのタブ。表示順・有効 |
| オプション | グループ（1つを必ず選ぶ／複数選べる）と選択肢（加算額0円可・既定・ステーション・売切） |
| 割引・クーポン | 金額／率、明細／会計全体、有効期間 |
| 従業員 | コード・PIN・権限（スタッフ／責任者／管理者）・手入力値引きの可否。管理者は管理画面のパスワードも持つ |
| レジ | レジ番号・名称・注文番号の発行モード |
| 店舗・運用設定 | 店舗情報・登録番号・レシートのヘッダー/フッター・税の端数処理・注文番号の範囲・営業日の切替時刻・キッチンの経過時間の閾値など |

- マスタは削除せず「無効」にする（過去の販売データが参照するため）。オプションの選択肢も同様
- 変更はすべて操作ログに記録する（価格変更は `product.price_changed` としても記録）
- 商品 CSV は BOM 付き UTF-8。カテゴリとオプショングループは名前で指定し（複数は `|` 区切り）、`id` が空の行は新規、値がある行は更新。1行でも誤りがあれば何も取り込まず、行番号つきで理由を表示する

## 注文の流れ（フェーズ3）

1. **レジ**: レジ番号を選ぶ → 従業員コード + PIN でログイン → （未開設なら）釣銭準備金を入れて開設
2. 商品を選ぶ（オプションは既定が選ばれた状態で開く）→ **店内／持ち帰りを必ず選ぶ**（税率と持ち帰り価格が決まる）→ 必要なら明細の「割引」や「会計割引」
3. 「会計へ」→ 現金（預り金を入れると釣銭を表示）か PayPay（金額を大きく表示し、お客様の画面で支払完了を確認して「支払確認済み」）→ 確定
4. 注文番号が大きく表示される。自動採番のレジは手書きの控えで、番号札のレジは番号札で渡す
5. **キッチン**: カードをタップすると、そのステーションの調理を完了にする（「すべて」表示なら全ステーション）。右の「直近に完了」から戻せる
6. **カスタマーモニター**: 会計すると「おつくり中」、呼び出すと「お呼び出し中」に大きく表示され、チャイムが鳴る
7. **ピックアップ**: 一覧のタップかテンキーで番号を選び、明細を確認して「呼び出し」→「受け渡し済み」。調理完了前でも呼び出せる。受け渡し済みは5分以内なら「呼び出し中に戻す」で戻せる（同じ番号が使われていない場合のみ）

- 金額は画面とサーバーで同じ計算（`packages/shared/src/pricing.ts`）を使い、確定時にサーバーで計算し直す。表示中に価格が変わっていたら確定せずに知らせる
- 通信が切れていると会計は確定しない。「再試行」は同じ冪等キーで送るので二重に登録されない
- 閉設は「レジ閉設」から。数えた現金を入れると、理論在高との過不足と PayPay 売上（PayPay 側との照合用）を表示する

## レシート（フェーズ4）

- 会計完了画面の「レシートを表示」で、80mm ロール紙と同じ並びのプレビューを出す。「PDF を開く」で同じ内容の PDF を新しいタブで開く
- 「再発行」すると【再発行】と明記したレシートになり、操作ログ（`receipt.reprinted`）に残る
- 記載項目: 店舗名・住所・電話番号・登録番号・日時・レジ番号・担当者・レシート番号・明細（オプション・割引を含む）・税率ごとの対象額と消費税額・合計・支払方法・預り金・釣銭・注文番号（自動採番では特大）・ヘッダー/フッター。軽減税率（8%）の明細には「※」を付けて注記する（適格簡易請求書の記載事項）
- 店舗名・登録番号・ヘッダー/フッターは管理画面の「店舗・運用設定」で設定する
- プリンターとキャッシュドロアは未導入のため、ダミードライバーが受け付けるだけ（サーバーのログに残る）。現金会計では会計確定時にドロアを開く指示も出している
- PDF のフォントは Noto Sans JP を同梱し、使った文字だけを埋め込む（インターネット不要）
- 領収書を求められた場合は、プリンター導入までは手書きで発行する

## 返金・商品変更（フェーズ5）

レジの「取引履歴」から行う。

1. 条件を入れなければ当日の営業日の取引が新しい順に出る。レシート番号（一部でも可）・注文番号・日付（過去の営業日も可）・金額・担当者で探せる
2. 取引を開き、明細ごとに返金する数量を選ぶ（「すべて選ぶ」で全額）
3. **選んだ数量を返金**、または **選んだ商品を変更**（代わりの商品を選ぶと差額を計算）
4. 理由を選ぶか入力し、**責任者（責任者・管理者）の従業員コードと PIN** を入れて確定する
5. 返金は元の支払方法で行う。現金は画面の金額をお返しする。PayPay は記録だけ残すので、PayPay の管理画面（またはアプリ）で返金する。変更で高くなった差額は元の支払方法でいただく

- 元の販売データは変更しない。返金・変更は元の取引に紐付く新しい取引（マイナスの取引）として記録し、**返金した日の営業日・返金したレジ**の売上（現金の在高）に計上する
- 割引のあった取引の一部返金は、割引を按分した後の「お支払いいただいた額」で返金する。何回に分けても合計は支払額と一致し、全額返金では元の税額がそのまま戻る
- 受け渡し前の注文は即座に反映する。全額返金なら注文は取消になりキッチン・お客様の画面から消える。一部返金・変更ならキッチンのカードに「変更あり」と出て数量が変わる（キッチンには通知も出る）。受け渡し済みの注文は状態を変えない
- 返金・変更のレシートには【返金】【商品変更】と元のレシート番号を載せる。操作ログに理由・承認者・金額を残す
